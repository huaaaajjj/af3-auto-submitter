🤖 AF3 Auto Submitter

AlphaFold Server 批量任务自动提交助手

本 fork 正式版 4.0.6：修复已提交批次无法确认导入的问题；历史扫描前自动选择官网每页 100 个。FASTA 标题作为任务名、每行序列一条蛋白链，每 30 个任务生成分批输入和官网 JSON，保存到所选本地文件夹后，明确确认才导入草稿。manifest 记录导入尝试、逐任务确认及预测完成状态；保留日期折叠、勾选提速和顶部账号。从 4.0 起统一使用 main 正式版，不再发布独立开发版。

升级前请备份油猴脚本及脚本数据；在原已安装条目内更新并核对账号，不要先卸载旧脚本。新建条目不能保证继承原 GM 账号记录。

安装 / 更新 4.0.6 正式版 查看正式源码

需要 Tampermonkey；请先备份并在原脚本条目内更新；禁用其他 AlphaFold 提交脚本，只启用一份

🚀 核心功能

📅 按日期应用勾选

按 Modified 日期查找 Completed 任务，确认倒序后越过开始日即结束，排序不确定时扫描所有分页。按天或逐项核对后应用到官网复选框；合并模式一次勾选全部，分开模式逐个勾选并提供“下一任务”。下载仍由你手动使用官网原生控件。

🖐️ 可移动、可调尺寸

正文与主要控件放大到 14px；拖动标题栏移动，拖动右下角手柄调节大小。刷新后恢复位置和尺寸，窄屏或缩放时约束在视口内，内容可滚动查看。

🧠 自动模式识别

能够自动识别当前是“草稿列表”还是“失败列表”，智能切换运行逻辑，无需手动设置。

♻️ Failed 克隆重提

对 Failed 任务执行 Clone and reuse 后重新提交；Confirm 只点击一次，等待官网新的成功消息，未确认时停止并锁定。

🛡️ 启动前确认

启动前显示当前模式、识别到的任务数量和计划处理数量，确认后才会开始自动操作。

⏸️ 暂停 / 停止

可暂停后续操作或停止批次；已发送请求仍会等待确认，停止不能撤回请求。

📋 完成汇总

批处理结束后会显示成功、跳过、失败数量，并列出跳过或失败任务的名称和原因。

🌐 多语言界面

默认中文，同时支持 English、日本語、한국어、Español、Français，语言选择会自动保存。

📝 可折叠日志

日志默认收起，不影响视线；需要排查跳过或失败原因时，可以在面板中展开查看。

✨ 4.0.6 正式版更新重点

  • 4.0.6 修复同名旧任务导致的历史核对失败：同名多条记录时，按已绑定任务 ID 或本次运行保存/提交后产生的唯一记录确定本批任务；本次已发送保存且脚本确认提交过同名任务时，Completed 等历史可确认导入并统计完成，无法唯一确定时仍停止。保留每页 100 个扫描，确认列表刷新后开始扫描，结束后保留 100；切换失败或页面条件变化时安全停止。保留官网翻页占位行和空草稿列表识别修复。脚本与更新元数据同步升版，可通过 Tampermonkey 检查更新升级。
  • 保留官网历史核对进度条，显示已扫描页数、记录数和稳定总数下的百分比；总数未知时显示不定进度。账号未识别、搜索未清空及页面条件变化时分别提示具体停止原因，核对结束保留结果。
  • FASTA 不再需要蛋白链模式：每个 >名称 作为任务名，后续每个非空序列行是一条蛋白链，下一个 > 开始新任务。只生成蛋白，每 30 个任务分一批；链不拼接、不自动拆肽，长链不要手动折行。输出 FASTA 保留完整链行，旧清单继续按原 JSON 恢复，输入错误不静默跳过。
  • 明确确认后才通过原生 Upload JSON 上传校验并保存草稿，不启动预测；核对全部名称和全绿状态，单击一次保存，再跨页确认草稿。manifest 记录逐批尝试、账号、时间、错误和逐任务导入/预测状态，结果不明时停止且不自动重导，已有目录可校验恢复；清单用版本检查和独占写入拒绝旧页面覆盖新记录，生成前检查大小及批次数上限。
  • 应用勾选只解析可能匹配目标的行及实际已勾选项，不再逐一读取无关旧任务的菜单。目标均有唯一 ID，且核验数与稳定的官网跨页勾选总数一致时提前结束；缺少唯一 ID 时仍遍历页面核对同名同时间歧义，不依赖日期排序，不跳过旧选择清理或勾选前后的身份核验。
  • 当前账号移到顶部“AF3 自动助手”旁边，不再占正文一行；窄面板自动换行，最多显示两行，悬停查看完整内容，保留实时更新和固定标题导航。
  • 下载匹配任务按日期默认折叠：日期标题保留任务数量和按天勾选，点击日期或使用键盘展开、收起当天明细。折叠不改变已选任务或逐个下载队列；全选、清空选择和应用仍包含收起的任务，切换语言保留展开日期。
  • 草稿本次数量不再受每页行数限制：输入 30 即以 30 为处理上限，等待官网成功通知和列表刷新后继续处理自动补入的草稿；加载空表不算耗尽，草稿用完时提前结束。确认框区分当前页行数与本次上限；Failed 重跑仍限当前页，不增加提交重试。
  • 修复油猴隔离环境的窗口对象无法传入 MouseEvent.view、导致草稿提交首次点击前中断的问题；共享点击函数同时覆盖失败任务重跑。保留鼠标事件链、单次提交和官网成功通知确认，不增加提交重试。
  • 按日期查找只为范围内任务读取唯一 ID；未搜索的官网默认 Modified 倒序列表或明确的 Modified 降序，在越过开始日后停止翻页并返回首页。起止当天均包含，不跳过开始日的其他任务。
  • 搜索结果没有明确倒序标记、其他排序、通用表格、日期无法识别或顺序异常时继续全量扫描，避免漏选；未知日期数量只统计已扫描页面。应用勾选及逐个队列的完整身份核验不变。
  • 真实官网的任务行可能没有结果链接：没有行内 ID 时，只打开该行原生三点菜单，读取 Open results 中的任务 ID，再关闭自己的菜单；不点击菜单项或触发下载。同名同时间任务分别保留，应用和逐个切换时重新核对身份。
  • 菜单读取期间请勿同时操作官网。已有菜单或对话框打开、菜单归属改变、读取期间任务行替换、账号或筛选变化时停止，不接管用户菜单；停止后仍清理自己打开的菜单。勾选后官网重建同一任务行时，重新读取候选行的菜单 ID，确认唯一一致后再继续，不读取已脱离页面的旧复选框。
  • 查找失败或结果为空时禁用“全选 / 清空选择”，保留真实原因，不再覆盖为“匹配 0 个”。
  • 现代化浅色面板：蓝墨文字、青绿色主操作和卡片分区；顶部标题与导航固定，正文独立滚动。提交数量有可见标签，下载按日期查找、核对任务、选择方式并应用排列，任务名称和 Modified 时间分行显示。账户页先显示已保存记录，再显示添加/编辑表单。
  • 账号目录改存 Tampermonkey 本机脚本存储，普通窗口和 InPrivate 共用账号、备注与额度记录。首次运行会合并当前窗口旧有的官网本地记录；升级后先在普通窗口打开一次官网以导入原有全部账号。要在 InPrivate 共用并保留目录，请允许 Tampermonkey 在 InPrivate 中运行，并将 Tampermonkey 设置 > Security > Store data in incognito mode 设为 Permanent。登录 Cookie 仍由 Edge 隔离，不保存密码或登录会话。
  • 无痕入口通过 Tampermonkey 直接打开 https://alphafoldserver.com/，由你在官网操作登录。所有 InPrivate 窗口共用临时 Cookie 会话；关闭全部窗口可从空会话重新登录。
  • 修复早期版本更新后面板消失：账户页改用 DOM 节点构建，兼容官网 Trusted Types 限制。更新后刷新官网即可恢复，已有本地账户记录和面板设置保留。
  • 新增账户管理页面：自动记录当前账号，也可手动添加邮箱、保存备注、编辑和移除本地记录；当前账号置顶标记。
  • 额度变更时自动记录，持续可读时每分钟更新记录时间，也可手动“记录当前额度”。其他账号显示上次记录及时间，未知额度不记为零，预览额度不写入账户记录。

  • 两个区域分别显示状态：仅选中 Saved draft 时上方显示草稿提交就绪，仅选中 Completed 时下方显示下载就绪；混选或未选标签时均待机。查找或应用下载选择时，运行状态只显示在下方。

📖 使用指南

1. 观察面板状态

脚本加载后，请留意屏幕右侧黑色面板上的“红绿灯”状态。脚本会告诉您当前能做什么：

😴 待机中
👈 请操作：
在 History 中仅选中
"Saved draft" (草稿)
或 "Failed" (失败)；
下载时仅选中 "Completed"
🟢 提交草稿
✅ 就绪：
仅选中 Saved draft。
点击启动将批量提交。
🔵 失败重跑
✅ 就绪：
仅选中 Failed。
点击启动将自动
Clone 并重试。

2. 运行流程

  1. 选择状态： 根据你的需求，在 History 中仅选中 Saved draft 或 Failed；混选或未选标签时无法启动。
  2. 调整每页显示： 建议在页面底部将 Rows per page 设置为 100，以减少翻页烦恼。
  3. 选择语言： 如果需要，可以在面板顶部切换界面语言；默认是中文。
  4. 设置数量： 在黑色面板输入框中，输入想要连续处理的任务数量（例如 10）。
  5. 一键启动： 确认面板底部提示文字无误后，点击 启动。
  6. 确认摘要： 启动前会弹出安全摘要，请确认模式和数量正确。
  7. 保持前台： 脚本运行期间，请勿关闭页面或最小化浏览器，这可能会导致模拟点击失效。
  8. 查看结果： 结束后会弹出完成汇总；如果有跳过或失败，可以展开日志查看原因。

3. 按日期勾选，再用官网下载

  1. 在官网 History 中仅选中 Completed，按需填写 Search History。未搜索的官网默认 Modified 倒序列表或明确的 Modified 降序，在越过开始日后提前结束；排序不确定时遍历所有分页，保留官网已有的复选框选中状态。
  2. 在面板下方常驻的“下载任务”区域，选择开始、结束日期，再点查找任务。按官网 Modified 显示日期筛选，包含起止当天；填写同一天即可选择一天。
  3. 结果按日期默认折叠，点击日期查看当天明细；日期前复选框按天勾选，展开后可逐项核对，也可点全选或清空选择。折叠不改变勾选或逐个下载队列。没有行内 ID 时会逐行打开原生三点菜单、读取 Open results 中的 ID，再关闭自己的菜单；不激活菜单项。同名同时间的不同 ID 任务分别保留。日期无法识别的任务不纳入结果，身份冲突或菜单无法安全读取时停止；查找失败或为空时保留原始提示。
  4. 选择合并一个 ZIP（官网最多 50 个）或分开下载（逐个勾选），再点应用到官网勾选并确认替换提示。合并模式勾选全部已核对任务，分开模式每次只勾选一个任务，均只应用勾选，不发起下载。
  5. 合并模式：手动点击官网原生批量 Download。分开模式：核对面板显示的当前任务名称、Modified 时间与序号，手动点击官网原生 Download，完成后点下一任务切换勾选，再手动下载。到最后一个任务时“下一任务”禁用。也可直接使用官网任务行的 Download。
  6. 下方下载区域显示待机 / 就绪 / 运行中，仅选中 Completed 时显示下载就绪；上方提交区域独立显示状态。点停止会停止查找或应用选择；应用中停止或出错可能留下部分勾选，不会自动恢复旧选择，请先核对官网复选框。
  7. 手动下载后，请在浏览器下载列表核对文件保存情况。浏览器询问时，按需允许官网的多个文件下载。

“应用到官网勾选”和“下一任务”会替换官网原有选择。合并模式可以应用超过 50 个任务，但官网合并 ZIP 每次最多 50 个任务；应用时会提示此限制，请自行减少官网勾选后再下载。脚本没有下载按钮或下载位置选项，不点击行下载或批量下载，也不自动拆批或在本地打包。“下一任务”仅切换勾选，不检测文件是否下载成功。

下载方式保存在当前浏览器本地。分开模式的队列只在当前页面有效；刷新、重新查找、修改日期、面板勾选、全选、清空、下载方式或官网筛选、搜索、排序、每页数量、复选框，都会使队列失效。面板选择或官网勾选变化后请核对并重新应用；日期或官网列表条件变化后请重新查找。停止或出错不会推进队列；停止后可重新应用，出错后需重新查找。

查找和应用选择期间保持页面打开，不要修改官网搜索、筛选、排序或每页数量；需要调整时先停止，再重新查找。应用完成后，可在官网调整勾选并手动下载。

⚠️ 免责声明 & 常见问题

维护者本地验证：以下合成页面检查不使用登录资料，也不访问 AlphaFold 或下载真实任务结果。

node --check af3-auto-submitter.user.js
python -I -X utf8 test_release.py
python -I -X utf8 test_submission.py
python -I -X utf8 test_download.py
python -I -X utf8 test_fasta.py
git diff --check
配额不足： 额度以官网为准；不足时停止，无法识别时不当作 0。请先核对官网状态，不要靠反复启动解决。
浏览器权限： 使用 Chrome 或 Edge 时，请确认 Tampermonkey 有权限在 alphafoldserver.com 上运行，相关扩展权限和后台运行权限没有被关闭。
面板不显示： 请确认本 fork 的 4.0.6 正式版 已安装且只启用一份，然后刷新 https://alphafoldserver.com/。访问 www.alphafoldserver.com 时也需相应站点权限。
  • 关于失败重跑： 脚本通过点击 "Clone and reuse" 实现重跑。该过程会产生页面跳转，速度较慢，请耐心等待脚本“补刀”。
  • 如果锁定或卡住： 先查看官网提示、面板日志及历史记录，核对任务和剩余额度。不要手动重复点击 Confirm。
  • 测试新版： 正式安装、检查更新和下载均来自本 fork 的 main；请只启用一份。提交结果不确定时，先查看官网历史记录和面板日志，不要手动重复点击 Confirm。
