🤖 AF3 Auto Submitter

AlphaFold Server 批量任务自动提交助手

本 fork 开发版 3.0.0-dev.3：修复账号切换沿用旧会话的问题，先退出官网再选择 Google 账号；账户管理保存多个账号、备注与额度记录。任务页提交在上、下载在下，常驻展开；下载由你手动点击官网原生 Download。功能仍在开发分支，尚未合并 main。

main 的 2.24.1 仍为旧行为基线，不包含这些 DEV 功能。

安装 / 更新 DEV 3.0.0-dev.3 查看开发分支

需要 Tampermonkey；请先禁用原版、旧 DEV 和其他 AlphaFold 提交脚本，只启用一份

🚀 核心功能

📅 按日期应用勾选

按 Modified 日期扫描当前 Completed 搜索结果的所有分页，按天或逐项核对后应用到官网复选框。合并模式一次勾选全部，分开模式逐个勾选并提供“下一任务”；下载使用官网原生控件，由你手动点击。

🖐️ 可移动、可调尺寸

正文与主要控件放大到 14px；拖动标题栏移动，拖动右下角手柄调节大小。刷新后恢复位置和尺寸，窄屏或缩放时约束在视口内，内容可滚动查看。

🧠 自动模式识别

能够自动识别当前是“草稿列表”还是“失败列表”，智能切换运行逻辑，无需手动设置。

♻️ Failed 克隆重提

对 Failed 任务执行 Clone and reuse 后重新提交；Confirm 只点击一次，等待官网新的成功消息，未确认时停止并锁定。

🛡️ 启动前确认

启动前显示当前模式、识别到的任务数量和计划处理数量，确认后才会开始自动操作。

⏸️ 暂停 / 停止

可暂停后续操作或停止批次；已发送请求仍会等待确认，停止不能撤回请求。

📋 完成汇总

批处理结束后会显示成功、跳过、失败数量，并列出跳过或失败任务的名称和原因。

🌐 多语言界面

默认中文，同时支持 English、日本語、한국어、Español、Français，语言选择会自动保存。

📝 可折叠日志

日志默认收起，不影响视线；需要排查跳过或失败原因时，可以在面板中展开查看。

  • 额度变更时自动记录，持续可读时每分钟更新记录时间，也可手动“记录当前额度”。其他账号显示上次记录及时间，未知额度不记为零，预览额度不写入账户记录。

  • 面板上方是提交任务，下方是下载任务，均不折叠；按天分组的匹配任务也直接列出，无需展开。
  • 仅选中 Saved draft 才显示草稿提交就绪，仅选中 Failed 才显示失败重跑就绪；混选或未选标签时待机并禁用启动，点击启动和确认后均重新核对标签。
  • 按日期查找任务：起止日期均包含当天，同一天可单独筛选；可按天或逐项核对，再应用到官网勾选。
  • 保留合并 ZIP / 分开下载两种方式：合并时一次应用全部勾选；分开时每次只选一个任务，并提供“下一任务”。下载均由用户点击官网原生 Download。
  • 应用选择会替换官网已有勾选；官网合并 ZIP 最多 50 个任务，超过时需自行调整，不自动拆批。
  • 两个区域分别显示状态：仅选中 Saved draft 时上方显示草稿提交就绪，仅选中 Completed 时下方显示下载就绪；混选或未选标签时均待机。查找或应用下载选择时，运行状态只显示在下方。

  • 拖动标题栏移动面板，拖动右下角手柄调整尺寸；位置与尺寸会在本地保存。
  • 实时显示官网 Remaining jobs，预览时优先读取预览额度；无法识别时明确提示。
  • 面板正文、日期输入与主要操作按钮为 14px，标题与启动按钮为 16px，辅助文字为 13px；窄面板日期自动排成一列，标题显示 DEV 版本号。
  • 拖动面板不再产生无用日志，日志只记录关键运行事件。

  • 汇总中会列出最多 5 个跳过或失败任务，方便非技术用户定位问题。

📖 使用指南

1. 观察面板状态

脚本加载后，请留意屏幕右侧黑色面板上的“红绿灯”状态。脚本会告诉您当前能做什么：

😴 待机中
👈 请操作：
在 History 中仅选中
"Saved draft" (草稿)
或 "Failed" (失败)；
下载时仅选中 "Completed"
🟢 提交草稿
✅ 就绪：
仅选中 Saved draft。
点击启动将批量提交。
🔵 失败重跑
✅ 就绪：
仅选中 Failed。
点击启动将自动
Clone 并重试。

2. 运行流程

  1. 选择状态： 根据你的需求，在 History 中仅选中 Saved draft 或 Failed；混选或未选标签时无法启动。
  2. 调整每页显示： 建议在页面底部将 Rows per page 设置为 100，以减少翻页烦恼。
  3. 选择语言： 如果需要，可以在面板顶部切换界面语言；默认是中文。
  4. 设置数量： 在黑色面板输入框中，输入想要连续处理的任务数量（例如 10）。
  5. 一键启动： 确认面板底部提示文字无误后，点击 启动。
  6. 确认摘要： 启动前会弹出安全摘要，请确认模式和数量正确。
  7. 保持前台： 脚本运行期间，请勿关闭页面或最小化浏览器，这可能会导致模拟点击失效。
  8. 查看结果： 结束后会弹出完成汇总；如果有跳过或失败，可以展开日志查看原因。

3. 按日期勾选，再用官网下载

  1. 在官网 History 中仅选中 Completed，按需填写 Search History。查找会遍历当前搜索结果的所有分页，并保留官网已有的复选框选中状态。
  2. 在面板下方常驻的“下载任务”区域，选择开始、结束日期，再点查找任务。按官网 Modified 显示日期筛选，包含起止当天；填写同一天即可选择一天。
  3. 核对结果，按天或逐个任务勾选，也可点全选或清空选择。日期无法识别的任务不纳入结果；任务名称及显示的 Modified 时间均相同、无法区分时，请缩小官网搜索范围后重新查找。
  4. 选择合并一个 ZIP（官网最多 50 个）或分开下载（逐个勾选），再点应用到官网勾选并确认替换提示。合并模式勾选全部已核对任务，分开模式每次只勾选一个任务，均只应用勾选，不发起下载。
  5. 合并模式：手动点击官网原生批量 Download。分开模式：核对面板显示的当前任务名称、Modified 时间与序号，手动点击官网原生 Download，完成后点下一任务切换勾选，再手动下载。到最后一个任务时“下一任务”禁用。也可直接使用官网任务行的 Download。
  6. 下方下载区域显示待机 / 就绪 / 运行中，仅选中 Completed 时显示下载就绪；上方提交区域独立显示状态。点停止会停止查找或应用选择；应用中停止或出错可能留下部分勾选，不会自动恢复旧选择，请先核对官网复选框。
  7. 手动下载后，请在浏览器下载列表核对文件保存情况。浏览器询问时，按需允许官网的多个文件下载。

“应用到官网勾选”和“下一任务”会替换官网原有选择。合并模式可以应用超过 50 个任务，但官网合并 ZIP 每次最多 50 个任务；应用时会提示此限制，请自行减少官网勾选后再下载。脚本没有下载按钮或下载位置选项，不点击行下载或批量下载，也不自动拆批或在本地打包。“下一任务”仅切换勾选，不检测文件是否下载成功。

下载方式保存在当前浏览器本地。分开模式的队列只在当前页面有效；刷新、重新查找、修改日期、面板勾选、全选、清空、下载方式或官网筛选、搜索、排序、每页数量、复选框，都会使队列失效。面板选择或官网勾选变化后请核对并重新应用；日期或官网列表条件变化后请重新查找。停止或出错不会推进队列；停止后可重新应用，出错后需重新查找。

查找和应用选择期间保持页面打开，不要修改官网搜索、筛选、排序或每页数量；需要调整时先停止，再重新查找。应用完成后，可在官网调整勾选并手动下载。

⚠️ 免责声明 & 常见问题

维护者本地验证：以下合成页面检查不使用登录资料，也不访问 AlphaFold 或下载真实任务结果。

node --check af3-auto-submitter.dev.user.js
python -I -X utf8 test_submission.py
python -I -X utf8 test_download.py
git diff --check
配额不足： 额度以官网为准；不足时停止，无法识别时不当作 0。请先核对官网状态，不要靠反复启动解决。
浏览器权限： 使用 Chrome 或 Edge 时，请确认 Tampermonkey 有权限在 alphafoldserver.com 上运行，相关扩展权限和后台运行权限没有被关闭。
面板不显示： 请确认本 fork 的 DEV 3.0.0-dev.3 已安装且只启用一份，然后刷新 https://alphafoldserver.com/。访问 www.alphafoldserver.com 时也需相应站点权限。
  • 关于失败重跑： 脚本通过点击 "Clone and reuse" 实现重跑。该过程会产生页面跳转，速度较慢，请耐心等待脚本“补刀”。
  • 如果锁定或卡住： 先查看官网提示、面板日志及历史记录，核对任务和剩余额度。不要手动重复点击 Confirm。
  • 测试新版： DEV 安装、检查更新和下载均来自本 fork 的开发分支；请只启用一份。提交结果不确定时，先查看官网历史记录和面板日志，不要手动重复点击 Confirm。
